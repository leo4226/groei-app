# i18n — Dutch / English language switching

**Date:** 2026-05-13  
**Status:** Approved  
**Scope:** UI strings only — botanical content (plant facts, species descriptions) stays Dutch for now.

---

## Problem

The app mixes Dutch and English UI strings inconsistently. Dashboard is almost entirely Dutch; Settings is mostly English; BottomNav is split. Dates are hardcoded to `nl-NL`. There is no way to switch language.

---

## Goals

- Support Dutch and English UI.
- Language preference is per-user, stored in the DB.
- Switching language updates the whole app instantly, no page reload.
- TypeScript enforces that both locale files have the same keys.
- Zero new npm dependencies.

---

## Non-goals

- More than two languages.
- Translating botanical content (plant names, facts, species descriptions) — follow-up work.
- Runtime translation / external translation APIs.

---

## Architecture

Four parts:

### 1. Locale files

`frontend/src/i18n/translations.ts` — shared `Translations` type.  
`frontend/src/i18n/nl.ts` — Dutch strings (default).  
`frontend/src/i18n/en.ts` — English strings.

Both locale files must satisfy `Translations` — missing keys are compile errors.

Each locale exports a `locale` string (`'nl-NL'` / `'en-GB'`) used in every `toLocaleDateString()` / `toLocaleTimeString()` call, replacing hardcoded `'nl-NL'` references throughout the codebase.

### 2. LanguageContext

`frontend/src/context/LanguageContext.tsx`

```tsx
const LanguageContext = createContext<Translations>(nl)

export function LanguageProvider({ children }: { children: React.ReactNode }) {
  const { users, activeUserId } = useFloreren()
  const user = users.find(u => u.id === activeUserId)
  const t = user?.language === 'en' ? en : nl
  return <LanguageContext.Provider value={t}>{children}</LanguageContext.Provider>
}

export function useT() {
  return useContext(LanguageContext)
}
```

`LanguageProvider` wraps the app in `main.tsx` (inside the Router, outside the pages). Re-renders automatically when the active user or their language changes.

### 3. `useT()` hook

One-liner hook that reads the context. Usage in components:

```tsx
const t = useT()
<button>{t.dashboard.actions.done}</button>
new Date().toLocaleDateString(t.locale, { weekday: 'long', ... })
```

### 4. Backend

- `language: str = 'nl'` column added to the `users` table (SQLite `ALTER TABLE`, default `'nl'`, no migration script needed).
- Existing user PATCH endpoint extended to accept `{ language: 'nl' | 'en' }`.
- `User` TypeScript type in `types/index.ts` gains `language: 'nl' | 'en'`.

```ts
    props: { zone: string; door: string; window: string; label: string; length: string; width: string; height: string; widthCm: string; hinge: string; left: string; right: string; inward: string; outward: string; openingDirection: string; wallThickness: string; outerWall: string; innerWall: string; cornerCut: string; corner: string; scaleCalibrate: string; scaleHint: string; delete: string }

```

The `care` keys match `care_type` values from the DB — `t.care[task.care_type]` works directly, replacing all `CARE_LABEL_NL` maps.

Functions like `daysLate` and `inDays` handle pluralisation inline (Dutch/English rules are simple).

## Settings UI

A language toggle added to the Settings page, directly under the user switcher:

```
┌─────────────────────────────────┐
│  Who's gardening?               │
│  [Leon]  [Lisbeth]              │
├─────────────────────────────────┤
│  Language / Taal                │
│  ┌──────────┐  ┌──────────┐     │
│  │ 🇳🇱 Dutch │  │ 🇬🇧 English│    │
│  └──────────┘  └──────────┘     │
└─────────────────────────────────┘
```

Section label is bilingual ("Language / Taal") so it's findable regardless of current language.

Tapping a button calls `PATCH /users/{id}` with `{ language: 'nl' | 'en' }`, updates the Zustand store, and the app re-renders in the new language instantly.

## Migration plan

Each step is independently shippable. Order: highest-impact first.

1. **Backend** — add `language` column to users table, extend PATCH endpoint, update TypeScript `User` type.
2. **Locale scaffolding** — create `translations.ts`, `nl.ts`, `en.ts`, `LanguageContext.tsx`. Wire `LanguageProvider` into `main.tsx`.
3. **`Dashboard.tsx`** — migrate all strings: `CARE_LABEL_NL`, greeting functions, section headers, button labels, date locale.
4. **`BottomNav.tsx`** — nav labels.
5. **`Settings.tsx`** — existing strings + new language toggle.
6. **Editor strings** — migrate `editorStrings.nl.ts` into `nl.ts` under `editor` key. Update all consumers. Delete `editorStrings.nl.ts`.
7. **Remaining pages & components** — `MapPage.tsx`, `PlantDetail.tsx`, `PlantCareDetail.tsx`, `MapSettingsPage.tsx`, `MapsListPage.tsx`, `AddPlant.tsx`, `PlanningCalendar.tsx`, sheets, map components.
